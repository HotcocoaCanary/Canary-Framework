# 架构

框架是普通 Python 类之上的一层薄封装。它把**声明**（写在类上的标记）与**解释**（读取
标记并驱动的引擎）分开。

## 分层

```
errors            异常，任何一层都可使用
   ▲
declare           声明层：phase / dep / introspect
   ▲
runtime           运行层：scope / invoke / advance / unwind
   ▲
canary            门面：Canary 基类与 dep()
```

依赖方向严格单向：`canary → runtime → declare → errors`。只有 `canary` 同时依赖两边，
那正是门面的职责。

这条约束不只是文档里的说法——`tests/test_layering.py` 用 `ast` 解析每个模块的 import
并断言方向，任何一次反向依赖都会让测试失败。

## 模块

| 模块 | 内容 |
|---|---|
| `core/errors.py` | 五个异常，全部继承 `CanaryError` |
| `core/declare/phase.py` | `Phase` 与 `init` / `start` / `stop` |
| `core/declare/dep.py` | `Dep` 描述符 |
| `core/declare/introspect.py` | 一次 MRO 遍历读出依赖与钩子，按类缓存 |
| `core/runtime/scope.py` | `Scope`、`scope_of`、无参构造 |
| `core/runtime/invoke.py` | 调用一个钩子 |
| `core/runtime/advance.py` | 沿依赖递归推进一个阶段 |
| `core/runtime/unwind.py` | 按台账逆序回收 |
| `core/canary.py` | `Canary` 基类与 `dep()` |

## 标记，而非改造

装饰器只在方法上写一个标记，从不改造类。单元因此保持普通类的一切性质：可继承、可混入、
可嵌套。

| 标记 | 由谁写入 | 由谁读取 |
|---|---|---|
| `__canary_phases__` | 阶段装饰器 | `introspect`（哪些方法属于哪个阶段） |
| `_canary_scope` | `Scope.adopt` | `Dep.__get__`（从哪里取回依赖） |

依赖不用标记表达，它就是一个类属性（`Dep` 描述符），因此持有的是类对象本身而不是名字。

## 钩子解析

一次 MRO 遍历同时收集依赖与带标记的属性名，结果按类缓存——声明在类创建之后不再变化。

钩子按**属性名**解析，因此语义与普通方法完全一致：

- 子类覆盖同名钩子即替换，需要叠加时使用 `super()`。
- 子类覆盖但不再标记时，该钩子不再运行。
- 不同名的混入钩子各自成立，基类在前。

## 两条规则

**推进**是唯一的递归。推进记录保存的是推进本身（一个 future）而非完成标志，因此
"未开始 / 进行中 / 已完成"三种情形不需要另设状态机：键不存在、未完成、已完成即是三态。
环检测也搭在同一处——环的唯一表现是遇到一个尚未完成、且位于当前路径上的单元。

深度优先加记忆化产生的完成顺序本身就是一个合法拓扑序，因此框架里没有独立的拓扑排序。

**回收**是唯一的不递归。依赖图不是树，回收因此按台账逆序线性进行。这是整个模型中唯一
一处不对称：构造可以分治，回收不行。

## 并发

一个单元的多个依赖同时推进，调度是依赖驱动的——每个单元只等自己的依赖。其中一个失败时
同批的其余依赖被取消并等待结束，异常组随后还原为那一个真实失败。

并发下的记账顺序仍是一个合法拓扑序（单元只在依赖全部完成后才进入），逆序回收因此依旧
正确。

单依赖时直接等待以省去一个任务，但每隔若干层改为创建任务，把调用栈交还事件循环，因此
依赖链的深度不受 Python 递归上限约束。

## 不变量

1. 单元一律由框架无参构造。
2. 一个作用域内，每个类型只有一个实例；两个各自构造的根是两张互不相干的图。
3. 装饰器只声明、不改造，单元保持普通类。
4. 依赖在 `@init` 之后才可用。
5. 全部 `@init` 完成之后，才有任何 `@start` 运行。
6. `stop()` 是唯一的回收路径，正常结束与失败结束共用，重复调用幂等。
7. 框架不认识任何外壳，接入宿主只有上下文管理器与三个显式方法两条路。
