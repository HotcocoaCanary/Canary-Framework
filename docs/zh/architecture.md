# 架构

框架是构建在 Python 原生对象与异步上下文管理协议之上的薄层。

## 分层模型

```
普通 Python Class
      │  @canary
      ▼
Canary
      │
      ├── __init__  → 构造 / 依赖注入
      ├── @start    → 启动 Hook  → __aenter__
      └── @stop     → 停止 Hook  → __aexit__
      ▲
Flock（可选编排器）
```

Canary 是一个普通 class 加上一个声明。`@canary` 记录元数据 —— 依赖参数名与生命周期 Hook 名 —— 并将该类重建为 `Canary` 子类，从而继承上下文管理协议与状态机。

## 两种使用方式

框架只有一个引擎，两种驱动方式：

- **在 `Flock` 下** —— 适用于完整应用。`Canary.run()` 返回一个 `Flock`，解析依赖图、排序，并按顺序执行构造与启动。
- **独立运行** —— 当你已拥有实例时。Canary 本身就是异步上下文管理器：

```python
async with database:
    ...
```

## 依赖发现

`@canary` 在装饰阶段按名称分类 `__init__` 参数（此时字符串注解无需解析）。在构图阶段，`Flock` 将每个依赖解析为具体的、已注册的 Canary 类型。这种拆分使得前向引用与可靠的循环检测成为可能。

## 顺序

依赖图决定一切顺序：

- **构造** —— 拓扑顺序。
- **启动** —— 拓扑顺序。
- **关闭** —— 逆拓扑顺序。
- **回滚** —— 逆拓扑顺序。

拓扑排序使用 Kahn 算法，以 `__qualname__` 打破并列，保证结果确定。

## 设计原则

1. **Canary 是最小运行单元。** 依赖、状态与生命周期都在一个 class 上。
2. **`__init__` 是依赖注入入口。** 无依赖 DSL。
3. **生命周期建立在 Python 原生协议上。** 启动 → `__aenter__`，停止 → `__aexit__`。
4. **`@start` / `@stop` 是声明式 API。** 框架将其接入协议，绝不注入魔法方法。
5. **所有 Hook 都可选。** 仅含依赖的 Canary 是完整的。
6. **装饰器不改变方法类型。** 静态类型检查器持续有效。
7. **依赖决定生命周期顺序。**
8. **`Flock` 只负责编排。** 它从来不是运行 Canary 的前提。
